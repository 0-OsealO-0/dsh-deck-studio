# dashi 两仓库测评：对 dsh-deck-studio 的可借鉴点与红线

测评对象：https://github.com/chuspeeism/dashi-ppt-skill （v0.4.14）、https://github.com/chuspeeism/dashi-ppt-campus （v0.4.15）
对照物：`dsh-deck-studio` v0.1.2（MIT，`deck` 工具，vendor 内置 ppt-master）
日期：2026-11-24

---

## 一、一句话结论

这两个仓库不是"PPT 生成器"，而是**一套设计资产 + 一套渲染/编辑/导出运行时**。它们正好补你插件的三块空白：固定版式与字段契约、浏览器内可编辑的产物、HTML DOM→PPTX 的保真导出。

但**代码一行都不能搬**：仓库根许可是 AGPL-3.0，导出引擎 `html-deck-to-pptx` 是闭源专有许可（禁止提取、再分发、用于其他产品）。所以价值排序是：

- 抄架构与契约：**8/10**
- 抄代码：**0/10**
- 当外部 skill 调用：**5/10**（可用，但要 Node 20+ / Chrome / 联网装依赖）

## 三、仓库 A 值钱的四个设计

### 1. 版式契约：把"版面"变成可查询、可校验的数据

`layout-manifest.json`（3.5 MB）里每个版式是：

```
{key, themePack, pageNumber, label, slot, dataLayout,
 controls[], countBindings, lengthBindings, numberBounds, freeTextFields}
```

- `controls`：旋钮/开关/下拉，带 `default/min/max/step`，直接对应浏览器控制面板。
- `countBindings`：`itemCount → ["items","stats","data"]`，数组显示几项由旋钮控制。
- `lengthBindings` / `freeTextFields`：每个槽的字数上限。
- CLI `inspect:layout --compact` 输出 `fillPlan`（标题/正文长度、可见数组数、媒体槽）+ `propShapes`（对象内部 key），**超字数在渲染期直接报错**，不是警告。

对你的意义：你的 `check` 只能查结构（溢出、对比度、字号登记），查不了"这页文案超预算"。这套契约把"版面约束"从散文变成 JSON，agent 写之前先查，门禁才有依据。

### 2. 渲染即编辑器：view-model 是真相，HTML 是投影

- 产物 HTML 内嵌 `<script id="deck-view-model" type="application/json">`；client-runtime 从它重建 React 树，控制面板实时改 props。
- 保存走 `persist-deck-state.mjs`：纯函数校验 state 形状（顺序/删除/复制必须是数组，props 必须是普通对象，variantSelection 必须非空），`data:` 媒体落盘 `assets/user-media/`，再用正则**原子回写**那一个 JSON script 块，其余 HTML 一字不动。
- 代码注释原话：*"写坏 index.html 比拒绝一次自动保存代价更大。"*

对你的意义：这是"产物即交付"的产品级答案。你的 HTML 是只读快照，改一个字要重跑 agent——这是你与它最大的体验差。

### 3. 混合导出引擎：映射不了就截图，但文字要抽回来

- 逐节点映射为 PPTX 原生对象；映射不了的区域整块截图为底图；**文字从实时 DOM 重新抽出来**写成可编辑文本框（无 OCR），alpha-matte 透明背景。
- 项目自报基线 `editableFidelity 0.851`（未独立验证）。
- DOM 契约：`#deck > .slide(.active)`，读 `data-editable-pptx-*` 注解，`activeSlideSelector` 可覆盖。

对你的意义：SVG→python-pptx 遇到渐变、滤镜、阴影、复杂路径会降级或报错；这套"底图 + 文字层"是保真的现实解。你已经有 Playwright 回渲和 `visual_review`，链路是现成的。

### 4. 文档与门禁工程：四道校验串联

`validate:goal-spec`（schema）→ `props:safe`（props 规范化/裁剪）→ 渲染 → `validate:goal-copy` → `validate:swiss`（HTML 结构）。其中 `validate:goal-copy` 很狠：

- 扫描**中性占位文案残留**（"请输入文本"）；
- 扫描**未在 goal.json 声明的模板默认文案残留**；
- 校验**输出正文是否命中用户目标关键词**；
- 校验 count 控件与封面候选使用。

另有值得抄的工程细节：依赖外置到 `~/.dashi-ppt/deps`（符号链接，`DASHI_PPT_DEPS_MODE=external`）、静默版本检查、npx 安装器 + 国内镜像、预览端口池 5200–5999、`seed` 稳定选页、`media:stage` 落 `assets/user-media/<hash>`。

## 四、仓库 B：campus 的真本事是"原生页"

- 12 所学校皮肤（含东南大学：accent `#12385F`、"建筑蓝图"、封面 343 号）。
- `brand` 层统一换校：`{school, name, logo, accent, chapters, fill, nav, titleStyle}`；每校 `meta.mjs` 是唯一允许写颜色字面量的地方，页面 CSS 只读 `var(--sch-*)`。
- 导出时把封面/目录替换成**设计师原生 PPTX 页**：3D 建筑模型可旋转、校园视频可播放。靠 `manifest.json` 的字段标记（`!!校名`、`!!图签-标签N`）定位；EMU 12192000×6858000；fonts 存 ascii 字宽表做溢出估算。
- 模板不随仓库发：`source.json` 分块 6 MB + SHA-256 + 多镜像（jsDelivr / jsdmirror / gh-proxy / raw），每校首下 45–90 MB。
- 选页对照表把学术场景映射到版式（研究背景→background_figure、技术路线→method_roadmap、公式→formula_notes…）。

对你的意义：SVG 永远做不出"真 3D / 真视频 / 真动画"，而学校模板、奖状证书恰恰是这类。**不必搬 45 MB 的 3D 模板**，用 1–2 页学院模板（封面+致谢）就能覆盖班级场景的大部分需求。

## 六、不建议照抄

1. **不要建 1000+ 版式库。** 它的 1020 版式是给陌生用户的大货架，背后是 3.5 MB manifest + metadata 生成器 + "DO NOT EDIT" 约束。你只有 3 个 profile，20–40 个参数化原型足够。
2. **不要把 React SSR + esbuild + playwright-core 搬进插件。** 你的栈是 Python + SVG，加 Node 运行时会翻倍安装成本与故障面。要 HTML 能力就扩展现有 `html` 动作。
3. **不要让编辑层成为第二个真相源。** dashi 用 view-model JSON 当真相、HTML 当投影；你若加编辑器，真相必须留在 `source.md`/JSON，SVG 每次重生成，否则两边漂移。
